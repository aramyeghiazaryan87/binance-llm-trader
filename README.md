# Binance LLM Trader

Торговый бот для **спота Binance**. Стратегия на правилах находит сигналы, **Claude** (Anthropic API) их фильтрует, читает новости, выбирает пары и пишет отчёты. Жёсткие лимиты риска заданы в коде, и LLM их обойти не может.

> ⚠️ Начинайте только с **testnet** (виртуальные деньги). Это учебный проект, а не финансовый совет. Большинство торговых ботов теряют деньги.

---

## Как это работает

```
Каждый час (после закрытия часовой свечи):

 Binance mainnet ──► топ-15 ликвидных пар ──► индикаторы ──► сигналы стратегии
 (реальные цены)         (∩ пары testnet)      EMA/RSI/ATR      (трендовый пробой)
                                                                       │
 RSS-новости + индекс страха и жадности ───────────────────────────────┤
                                                                       ▼
                                                     Claude Sonnet 5.5 (1 вызов в час)
                                                     • режим рынка: risk_on / neutral / risk_off
                                                     • watchlist: на каких парах торговать
                                                     • одобрить или отклонить каждый сигнал
                                                     • держать или закрыть открытые позиции
                                                     • короткий отчёт на русском
                                                                       │
                                                                       ▼
                                          Проверка ответа + риск-менеджер (жёсткие лимиты)
                                                                       │
                                                                       ▼
                                          Рыночный ордер на testnet ──► Telegram + журнал

Каждые 5 минут (без LLM, бесплатно): стоп-лосс, трейлинг-стоп, лимиты просадки.
Раз в день: отчёт в Telegram.
```

### Стратегия «Трендовый пробой» (только покупка, без плеча)

**Вход** на закрытой часовой свече, если выполнены все условия:
1. цена выше EMA200 (долгосрочный тренд вверх);
2. EMA20 выше EMA50 (среднесрочный тренд вверх);
3. закрытие выше максимума предыдущих 20 свечей (пробой);
4. объём не меньше 1.2 × средний за 20 свечей;
5. RSI(14) от 50 до 78 (импульс есть, сильной перекупленности нет);
6. ATR от 0.3% до 6% цены.

**Фильтр рынка** (`REGIME_FILTER=true`, включён по умолчанию; выключить: `REGIME_FILTER=false`): новые входы только когда BTC закрылся выше своей дневной EMA200. На падающем рынке пробои отдельных монет чаще оказываются ложными. Фильтр проверяется в коде до вызова Claude, обойти его LLM не может. Если дневные свечи BTC недоступны, входов нет. Открытые позиции фильтр не трогает: их защищают стопы.

**Выход:**
- стоп-лосс: вход − 2 × ATR;
- трейлинг-стоп: максимум с момента входа − 3 × ATR (стоп только поднимается);
- стоп по времени: через 96 часов;
- досрочно, если Claude советует закрыть позицию с уверенностью от 70%.

После срабатывания стоп-лосса пара уходит на паузу на 6 часов.

### Роль Claude

| Задача | Что делает |
|---|---|
| Выбор пар | Из 15 самых ликвидных пар выбирает до 5, на которых сейчас стоит торговать |
| Фильтр сигналов | Каждый сигнал стратегии одобряет или отклоняет, задаёт уверенность и множитель размера (0.25–1) |
| Новости | Оценивает заголовки CoinDesk, Cointelegraph, Decrypt и индекс страха и жадности |
| Позиции | Советует держать или закрывать открытые позиции |
| Отчёты | Пишет 2–3 предложения на русском: что на рынке и что решено |

Что Claude **не может**:
- открыть сделку без сигнала стратегии;
- увеличить размер позиции сверх лимита;
- отменить стоп-лосс.

Ответ модели приходит в строгом JSON (structured outputs). Код проверяет каждое поле: неизвестные пары и сигналы отбрасываются, числа ограничиваются допустимыми диапазонами. Заголовки новостей передаются как недоверенные данные внутри блока `<news>`.

**Стоимость:** модель `claude-sonnet-5-5`, effort `low`, примерно $0.01 за вызов. При вызове раз в час это около $7 в месяц. Лимит **$10 в месяц** соблюдает сам бот:
- перед каждым вызовом он проверяет, что потрачено + худший случай для этого вызова ≤ $10;
- если расход обгоняет график месяца, часы без сигналов пропускаются;
- когда бюджет исчерпан, бот переходит в `LLM_FAIL_MODE` (по умолчанию `hold`: новых входов нет, стопы работают).

Включён server-side fallback (`fallbacks: "default"`): если модель откажет по политике безопасности, API само повторит запрос на запасной модели. Его стоимость тоже учитывается. Отключить можно через `LLM_FALLBACKS=false`.

### Лимиты риска (настраиваются в `.env`)

| Лимит | По умолчанию |
|---|---|
| Риск на сделку (потеря при срабатывании стопа) | 1% капитала |
| Максимальный размер позиции | 20% капитала |
| Одновременно открытых позиций | 4 |
| Всего в монетах | 80% капитала |
| Дневной убыток, после которого входы запрещены до конца дня (UTC) | 3% |
| Просадка от пика → **аварийная остановка** (продать всё, сделки запрещены) | 15% |

## Быстрый старт на testnet

### 1. Ключи Binance Testnet (бесплатно)
1. Откройте https://testnet.binance.vision и нажмите **Log In with GitHub**.
2. Нажмите **Generate HMAC_SHA256 Key**, задайте название, например `llm-bot`.
3. Сохраните **API Key** и **Secret Key**. Secret показывается один раз.
4. Виртуальный баланс выдаётся автоматически. Бот использует весь свободный USDT (можно ограничить через `BUDGET_USDT`).

> Testnet примерно раз в месяц сбрасывается: балансы и ключи обнуляются. Тогда создайте новые ключи и выполните `python -m trader reset --yes`.

### 2. Ключ Claude API
1. Откройте https://platform.claude.com → **API Keys** → **Create Key**.
2. Пополните баланс (Billing) и **установите лимит расходов** (Limits): это вторая страховка поверх лимита в коде.

> Подписка Claude Pro/Max **не** включает API: оплата отдельная.

### 3. Telegram (необязательно)
1. В Telegram напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и скопируйте токен.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": 123456789}`.

### 4. Установка
Нужен Python 3.11+.

```bash
git clone https://github.com/<ваш-логин>/binance-llm-trader.git
```

```bash
cd binance-llm-trader
```

```bash
python3 -m venv .venv && source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

```bash
cp .env.example .env
```

Откройте `.env` в редакторе и заполните `BINANCE_TESTNET_API_KEY`, `BINANCE_TESTNET_API_SECRET`, `ANTHROPIC_API_KEY` и, если нужно, Telegram.

### 5. Проверка (ордера не ставятся, Claude не вызывается)
```bash
python -m trader check
```
Команда проверяет доступ к Binance, ключи testnet и баланс, список пар, текущие сигналы, новости и ключ Claude. Для ключа используется бесплатный подсчёт токенов, заодно выводится оценка стоимости вызова. Также проверяется Telegram.

### 6. Один цикл вручную
```bash
python -m trader once
```

### 7. Постоянная работа
```bash
python -m trader run
```
Остановка: `Ctrl+C`. Бот завершит текущий шаг.

### Бэктест

Прогоняет правила стратегии по истории часовых свечей с теми же стопами, лимитами риска, комиссией и проскальзыванием, что в paper-режиме. Claude не вызывается: каждый сигнал считается одобренным. Так проверяются сами правила, без фильтра LLM.

```bash
python -m trader backtest --days 90
```

Чтобы сравнить с другими настройками, добавьте варианты. Ключи те же, что в `.env`, плюс параметры стратегии (`RSI_MIN`, `RSI_MAX`, `MIN_ATR_PCT` и т.д.):

```bash
python -m trader backtest --days 180 --variant "25 пар:UNIVERSE_SIZE=25" --variant "объём x1.0:MIN_VOLUME_RATIO=1.0"
```

Команда показывает сделки в неделю, долю прибыльных, среднюю сделку после комиссий, profit factor, итог, максимальную просадку, лучшие и худшие пары, а также доход BTC «купить и держать» за тот же период.

Список пар бэктест выбирает так же, как бот: каждый час берёт топ-`UNIVERSE_SIZE` по объёму за предыдущие 24 часа. Кандидатами служат все пары к USDT, включая делистнутые. Иначе в тест попали бы только сегодняшние лидеры, то есть монеты, которые уже выросли, и результат был бы завышен. Первый запуск загружает дневные свечи примерно по 700 парам, это занимает несколько минут. Быстрый, но оптимистичный режим по сегодняшнему топу: `--universe today`.

Смотрите на разные периоды (`--days 90`, `180`, `360`), а не на один удачный. Для периода длиннее месяца бэктест печатает доход по месяцам рядом с изменением BTC.

Аварийная остановка: живой бот после просадки 15% перестаёт торговать, пока вы не выполните `reset-kill-switch`. В бэктесте по умолчанию остановка снимается через 3 дня, иначе после первого обвала год бы просто стоял. `--kill-reset-days 0` оставит остановку навсегда, как у бота.

Свечи загружаются в 6 потоков и сохраняются в `data/candles/` (папка в `.gitignore`). Следующий запуск докачивает только новые свечи. Отключить кэш: `--no-cache`.

## Режимы

| `TRADING_MODE` | Деньги | Ключи | Цены для сигналов | Где исполняются ордера |
|---|---|---|---|---|
| `testnet` (по умолчанию) | виртуальные | testnet.binance.vision | mainnet | testnet |
| `demo` | виртуальные | Binance Demo Trading | mainnet | demo-api.binance.com |
| `paper` | виртуальные | не нужны | mainnet | симуляция в боте (комиссия 0.1% + проскальзывание) |
| `live` | **реальные** | Binance API | mainnet | Binance |

**Почему сигналы считаются по ценам mainnet:** на testnet цены и объёмы часто искажены (мало участников, случайные всплески). Сигналы считаются по реальному рынку, ордера исполняются на testnet. Если цена на testnet отличается от реальной больше чем на 3%, вход пропускается.

### Переход на реальные деньги (не раньше чем через 4+ недели стабильной работы на testnet)
1. На binance.com: Profile → API Management → Create API. Права только **Enable Reading** и **Enable Spot & Margin Trading**. **Вывод средств выключен.** Включите **Restrict access to trusted IPs** с IP вашего VPS.
2. В `.env` задайте `TRADING_MODE=live`, `BINANCE_API_KEY`, `BINANCE_API_SECRET`, `LIVE_TRADING_CONFIRM=I_UNDERSTAND_THE_RISK` и обязательно небольшой `BUDGET_USDT` (например, 100).
3. Учтите, что стопы бот держит программно: если он выключен, стопы не работают.

## Где смотреть результаты

- **Telegram**: сделки, ошибки, ежедневный отчёт (`DAILY_REPORT_HOUR_UTC`).
- **Логи**: `data/trader_<режим>.log`.
- **База**: `data/trader_<режим>.db` (SQLite). Таблицы:
  - `positions`: позиции и результат каждой сделки;
  - `trades`: ордера;
  - `llm_calls`: каждый вызов Claude с токенами и стоимостью;
  - `decisions`: полный ответ LLM и итог каждого цикла.

  Открыть можно, например, в DB Browser for SQLite или командой:
  ```bash
  sqlite3 data/trader_testnet.db "select symbol, pnl_usdt, exit_reason from positions"
  ```

## Можно ли запустить в облачной сессии Claude Code?

Только для теста и только в режиме `paper`. Binance отвечает `451 restricted location` на IP облачных серверов Claude, **в том числе testnet**, поэтому ордера на testnet оттуда не проходят. Для теста логики, Claude, новостей и Telegram на реальных ценах:

1. В настройках среды (Network access → Allowed domains) добавьте `data-api.binance.vision`. Это официальный эндпоинт Binance только для публичных рыночных данных.
2. Ключ Claude задайте в переменных среды под именем `TRADER_ANTHROPIC_API_KEY`. Переменную `ANTHROPIC_API_KEY` облачная среда в сессию не передаёт: она зарезервирована под авторизацию самого Claude Code.
3. В новой сессии выполните:
   ```bash
   TRADING_MODE=paper MARKET_DATA_URL=https://data-api.binance.vision python -m trader once
   ```

Настоящую торговлю на testnet запускайте на своём компьютере или на VPS в стране, где Binance работает.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `451` / `restricted location` | Binance недоступен из страны сервера (так же и из облака Claude): запускайте на компьютере или VPS в другой стране |
| `CERTIFICATE_VERIFY_FAILED: self-signed certificate` на `api.binance.com` | Соединение с Binance перехватывает сеть: VPN, антивирус, провайдер. Бот правильно отказывается соединяться. Проверку TLS не отключайте. Возьмите рыночные данные с официального адреса Binance для них: `MARKET_DATA_URL=https://data-api.binance.vision` в `.env`. Если в VPN есть «защита веба», добавьте исключение для `*.binance.com` и `*.binance.vision` |
| `Timestamp for this request is outside of the recvWindow` | Отстают часы сервера: `sudo timedatectl set-ntp true` |
| `Invalid API-key, IP, or permissions` | Ключ не от того режима (testnet ≠ live), нет права Spot Trading или IP не в белом списке |
| `LLM: disabled` | Не задан `ANTHROPIC_API_KEY` (в облаке Claude Code: `TRADER_ANTHROPIC_API_KEY`) или `LLM_ENABLED=false` |
| `LLM: skipped … бюджет` | Месячный лимит или экономия по графику; в новом месяце вызовы возобновятся |
| Сигналов нет часами | Это нормально: стратегия ждёт пробоя в восходящем тренде. В падающем рынке входов не будет |
| После сброса testnet позиции «закрыты в учёте» | Монеты исчезли со счёта, бот провёл сверку. Сделайте `reset --yes` |

## Разработка

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest -q
```

Тесты работают офлайн, без ключей и сети:
- фейковая биржа, paper-исполнение и фейковый Claude;
- полный цикл: сигнал → одобрение LLM → покупка → стоп-лосс → пауза → перезапуск;
- аварийная остановка, бюджет LLM, разбор ордеров;
- контракт с настоящим SDK Anthropic: проверяется формат запроса.

Структура:
```
trader/
  config.py       настройки из .env
  market_data.py  свечи и тикеры, выбор пар
  indicators.py   EMA, RSI, ATR
  strategy.py     сигналы входа и правила выхода
  news.py         RSS и индекс страха и жадности
  llm.py          Claude: промпт, схема ответа, проверка ответа
  budget.py       учёт расходов и лимит $ в месяц
  risk.py         размер позиции и лимиты
  broker.py       ордера (ccxt) и paper-симуляция
  engine.py       главный цикл
  reports.py      статус и отчёты
  storage.py      SQLite
  __main__.py     команды
```
